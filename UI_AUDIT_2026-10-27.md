## Corrections implemented in this pass

| Finding | Cause | Correction |
| --- | --- | --- |
| Material caption letters cut off above and below their lines | SplitText masks used the untransformed line height while words were stretched to 135% | Added clearance inside each mask with compensating negative margins; kept the diagonal photo wipes and staggered line reveals. |
| Wrapped concept headings clipped on narrow phones | A reveal line can contain multiple physical text lines; the stretched block exceeds the mask | Added extra heading clearance and adjusted the concealed animation positions to keep the full text hidden before its entrance. |
| Hero letter masks had too little room for serif overhangs | Tight per-character clipping boxes | Expanded the character masks while retaining the original spacing and letter stagger; moved the concealed starting position beyond the expanded mask so letter tips do not peek through before entry. |
| Invisible opening title intercepted hotspot input | Its full-screen layer retained pointer events after opacity reached zero | Made the decorative title layer ignore pointer events. |
| An open hotspot card could block its own marker on touch screens | The card overlapped the marker and intercepted taps | Made informational cards transparent to input; retained mouse hover, added explicit touch-safe pointer handling and outside-click/Escape dismissal. |
| Russian/Georgian manifesto words extended beyond phone screens | English-oriented minimum sizes and a rigid country/workshop row | Applied smaller translated display sizes on phones and allowed the row to wrap. Desktop display sizes remain unchanged. |
| Localized editorial heading exceeded narrow-phone/tablet width | Large minimum sizes, script rotation and a non-wrapping row | Allowed wrapping and adjusted phone typography for the longer translations. |
| Service photo nearly disappeared on a 320 × 568 phone | Fixed vertical spacing left insufficient room inside the viewport | Added a short-phone composition with reduced spacing, heading size and a bounded photo height. |
| Several sections ignored reduced-motion preferences | Circle reveal, manifesto and quote parallax created scroll transforms unconditionally | Scoped spatial scroll effects to the motion preference, reverted them when preferences change, and stopped the rotating emblem in reduced motion. |
| Localized script accents fell back to an unrelated generic cursive face | Pinyon does not provide the required Georgian/Russian glyphs | Added explicit existing editorial-font fallbacks. |
| Browser regression script checked a retired homepage | Its selectors expected the old films/service rows/header menu | Replaced the npm entry point with checks against the mounted ERA components and current navigation. |

The masks still conceal moving text. Increasing clearance must not be replaced with global `overflow: visible`, which would expose letters before their entrance and break the intended reveals.

## Remaining issues, in recommended order

### 1. Correct commercial promises before promoting the site — high priority

Owner information supplied in this conversation describes approximately two months for an overall project, with project-dependent design, revisions, processing, painting/router work and installation. Current dictionaries still advertise several shorter service timelines, 1–3 day installation, work "under one roof", and an unconditional price-never-changes statement.

Update every locale and relevant About/FAQ/category copy together. Explain supplier involvement, the scope of agreed quotations, location-dependent logistics and customer-requested revisions accurately. Preserve the distinction between furniture design at ₾30/m² of front elevation and interior design at US$15–20/m² of floor area. These are reported design fees, not furniture manufacturing prices.

Relevant sources: `messages/home-*.json`, main locale dictionaries, `lib/site.ts`, and `lib/structured-data.ts`.

### 2. Make kitchens easier to reach and enquire about — high priority

The owners confirmed kitchens are the acquisition priority. The homepage service carousel explains services but does not currently provide a direct category link for each service. Add discreet contextual links to the existing kitchen/category pages, retain the current visual style, and improve those pages with confirmed buyer information and real projects.

### 3. Unify contact attribution — high priority

The manifesto and editorial WhatsApp links, and the editorial phone link, bypass the existing `ContactLink` flow. The About page has another direct WhatsApp route. They can open the correct contact destination while missing the consistent event/reference context collected elsewhere. Reuse the existing contact helper and verify a customer enquiry can be linked to an actual quotation/order.

### 4. Complete non-JavaScript interaction fallbacks — medium priority

All service/hotspot/FAQ copy remains in initial HTML. This is distinct from making every control usable without JavaScript: contact-opening buttons, carousel selection and collapsed FAQ panels still need deliberate progressive-enhancement fallbacks. Direct phone/WhatsApp anchors are available. The collection no longer starts behind a circular clip when JavaScript is disabled.

### 5. Review readability and input targets — medium priority

Some metadata and controls use 9–10px text. Muted material labels and HUD text over bright photographs can be difficult to read. Perform measured contrast and target-size checks, then make restrained local adjustments. No numerical contrast-compliance claim is made in this audit.

### 6. Harden sitemap and CMS edge cases — medium priority

The sitemap catches a gallery-list failure and can return a cacheable successful response containing only static pages. Preserve the last valid complete result or return an appropriate non-cacheable failure. Gallery `lastmod` uses creation time; correct update timestamps require coordination with the separate admin/backend. Blank/fallback image descriptions also need a consistent CMS policy.

### 7. Establish production performance evidence — medium priority

Measure the deployed mobile experience before choosing optimizations. Next.js 16 documents the hero's `priority` image property as deprecated. Choose the loading strategy based on which image is actually important on entry; avoid preloading every below-fold image. Verify font/image transfer costs and real LCP, CLS and INP separately from local functional checks.

### 8. Verify deployment and establish a traffic baseline — before judging growth

Local changes do not prove the live site has updated. After deployment, rerun the same SEO/browser checks against the deployed URL and record the revision. Use Search Console query/page exports and enquiry/order records to compare results. Partnerships and the proposed AI designer remain future work; neither is required to finish these corrections.
